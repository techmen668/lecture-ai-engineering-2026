- 取り組んだレベル：基礎 

- やったこと（変更したファイル・設定・処理、または設計した取得方法）：

    app/agent.pyファイルのTREE_INSTRUCTIONSにて、brouse_treeに関する記述に変更を加えた。演習パートにて概念・パラメータともに質の高い回答が返ってきたが、その回答を返す構造がどこにあるのか？ということを構造的につかむのが目的。brouse_treeの呼び出しを意図的に制限して、演習実施時よりも質の低い回答が返ることで構造の対比ができるということを意図している。

    実際にファイルに加えた変更は以下の通りである。変更前の実行結果は演習パートでの実施内容を用いる。

    変更前（演習）
    ページ候補には先頭文だけが含まれる。関係するページIDで browse_tree を呼び、nodeの全文を読んでから回答する。

    変更後（宿題）
    ページ候補に表示された先頭文だけを根拠として回答する。
    ページIDを指定して browse_tree を呼ばない。


- 比較した質問と、固定した条件（モデル・対象資料など）：
　
    比較した質問・・・第2回の説明では、LoRAは何を固定し何を学習しますか？ QLoRAは何を 加えますか？
    固定した条件・・・回答モデルはgemini-3.5-flash-lite、対象資料は第1〜3回の本講義資料、実行モードはTree。変更前後で同じ質問を使い、どちらも uv run python -m app.agent --tree --trace で実行した。比較した変更は TREE_INSTRUCTIONS のみ。

- 結果（変更前後の回答・根拠、`--trace`の出力、時間・トークン数・生成API推定費用など）：
　
    ＜変更前＞
    
    LoRAの元の重みを固定し、低ランク行列を学習すること、QLoRAでは元の重みを4bit量子化することに加え、付箋のたとえやGPU1台で調整できる点まで説明した。traceでは目次をたどった後、lec02-main-p052を指定して本文717文字を取得していた。5.25秒、入力9,219／出力284 tokens、モデル応答5回、推定費用$0.003476。　

    ＜変更後＞

    固定・学習するものと4bit量子化について回答し、p.52を引用したが、説明はより簡潔だった。traceでは第2回の目次と章のページ候補までで終わり、p.52の本文取得は確認できなかった。5.04秒、入力5,307／出力230 tokens、モデル応答4回、推定費用$0.002167。

    両方とも質問の要点には回答しているが、変更後は回答の詳細さが減り、引用先の本文を取得した証拠もtraceにないため、p.52による裏付けを確認しにくい。本文取得を省いたことで入力トークン数と推定費用は減ったが、資料の根拠を追跡できる度合いも弱まった。なお、各条件1回の実行結果であり、回答の違いを指示文の変更だけによるものとは断定できない。　


- 改善した例と、残る失敗・制約：

    今回の実行によって、browse_treeの呼び出しがtreeの回答の質を高めているということは構造的に掴むことができたのではないかと考えている。ただし今回は実行が一回のみであることと、変更後は資料の根拠追跡があいまいになりつつもある程度は回答の質を担保した状態になったので、試行回数を増やしたり改変箇所を変えてみる等の検証の余地はあるので今回だけでは断言しきれない面も大きい。
